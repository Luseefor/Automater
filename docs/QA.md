# Release QA matrix

Before each release, run `swift test`, then exercise the app on a clean macOS user account with Accessibility initially disabled.

| Area | Targets | Expected result |
| --- | --- | --- |
| Permissions | Automater | Clear prompt and recovery after Accessibility is granted |
| Foreground clicking | Calculator, TextEdit | Correct click count; emergency stop works |
| Keyboard repeat | TextEdit | Single keys and shortcuts honor interval and repeat count; Stop cancels the startup countdown and continuous playback |
| Background keyboard | TextEdit | Keys go to the selected app; a missing target stops playback without sending foreground keys |
| Compact panel | 480 × 520 minimum, enlarged window | Repeat/Macros tabs, inline app menu and pinned Start/Stop remain usable; Advanced expands without clipping controls |
| Appearance | Light, Dark, System; all accent colors | Changes apply to the panel, settings and floating controls immediately and survive relaunch |
| Identity and menu bar | Dock, title bar, menu bar | Tandem mark is visible; menu bar can reopen the compact panel, Settings and Clipboard; unavailable playback/stop actions are disabled; live status and global shortcuts work while the menu stays open; visibility preference survives relaunch |
| Clipboard history | Five distinct copies, text, images, file references | Every captured item can be retrieved; pins survive relaunch; copied-history items do not duplicate themselves |
| Clipboard paste | Previous app, countdown, emergency stop | Paste targets the previous external app; Stop All or starting repeat/recording cancels pending paste |
| Clipboard controls | Search, pin filter, pause, clear | Selection follows filters; paused and concealed copies are not retained; clearing removes unreferenced images |
| Compact controls | Mouse, Keyboard, finite repeat, macros | Native menus display their selection and route changes; point settings appear only for mouse actions; macros remain editable in one pane |
| Background clicking | Native two-window fixture; Brave button and canvas fixture | Only the selected window receives clicks while another app stays active; pointer remains still; local point follows window movement |
| Missing background target | Unselected target, closed window, exited app | Run stops with zero further clicks; never falls back to foreground input |
| Incompatible target | A target with no AX windows | “Foreground recommended”; no claim that background input will work |
| Coordinates | Two displays, scaled display, moved window | Fixed and multi-point targets remain accurate |
| Macro recording | Native fixture, TextEdit | Clicks, holds, drags and scrolls retain window-local coordinates; text keeps app identity; sessions reset modifier state; app hotkeys are excluded |
| Macro playback | Foreground and Background; finite and continuous loops | Pauses precede their actions; order and loop counts hold; closed targets stop; keyboard/text macros explicitly require Foreground |
| Global shortcuts | Another app active | Toggle repeat, record, play/stop macro, Stop All, grab point and Clipboard route to their actions; malformed bindings are rejected |
| Application menus | Automater, File, Edit, View, Controls, Clipboard, Window, Help | Macro file actions, unsaved-change prompts, native text editing, panel shortcuts, appearance, clipboard search/pause, window close/reopen, About and Help work; Quit stops active playback |
| Upgrade | Previous signed build | Settings and macros survive an app upgrade |

The real-app matrix is a compatibility test, not proof that every third-party app accepts automated input.

Multi-point burst audit on 2026-10-18 (Tandem 0.3.5): 138 automated tests passed, including 10 burst tests for full-round order/counts, missing-target preflight, cancellation inside a 1,000-point burst, balanced event pairs, native window identity/coordinates, sequential compatibility, config propagation and re-pick reset. Installed-app tests captured three points without clicking controls, moved the second point in place, and delivered the exact order across two native windows. Four background runs, including a moved window, acknowledged all three clicks in 48–53 ms; foreground took 27 ms. Finite and continuous rounds, the between-round interval, and global Stop passed. The timing measures first-to-last target acknowledgement, excluding preparation. Fast background routing uses an optional non-public CoreGraphics window-location symbol; Accessibility is retained when unavailable, and some targets or inactive Spaces can be slower. Temporary fixtures were removed and modified Repeat settings restored. See the [burst audit](../output/qa/multipoint-burst-audit-2026-10-18.json).

Clipboard cleanup audit on 2026-10-18 (Tandem 0.3.4): 128 automated tests passed, including 13 new retention tests using isolated pasteboards, temporary repositories and separate preferences. Coverage includes age boundaries, pinned exemptions, copy caps, immediate policy changes, startup and paused/idle cleanup, persisted preferences, selection repair, expired image removal and unpinning. A recursive limit observer was caught and fixed before installation. The installed native Clipboard Settings controls and both option menus were checked through Accessibility without changing cleanup preferences or reading the system clipboard. Screen capture was unavailable in this session, so no screenshot inspection is claimed. The signed installed binary matches dist and passes strict signature verification. See the [clipboard cleanup audit](../output/qa/clipboard-cleanup-audit-2026-10-18.json).

Background macro audit on 2026-10-18 (Tandem 0.3.3): 115 automated tests passed. Installed-app tests recorded three actions across two exact native windows and replayed four loops (12/12) while another app remained active, including from its fullscreen Space. Fresh recording → switch Space → first playback passed without a warm-up replay; saved macro → restart → load → switch Space also delivered 12/12. Loops followed a window moved 200 points while the pointer was used elsewhere. Saved macros retained their own playback mode. Continuous playback and global Stop worked; mixed keyboard macros stopped before any background click; minimized and closed targets stopped without sibling or foreground clicks. The close fixture retains CG metadata, so its error reads “cannot be reached.” A separate close-test focus measurement was invalidated by unrelated native input and is not counted as a pass. Cross-Space coverage is limited to Accessibility-backed left single clicks with prepared window handles; a cold launch away from targets can require visiting their Space once. The installed binary matches dist and passes strict signature verification. See the [background macro audit](../output/qa/background-macros-audit-2026-10-18.json).

Recording audit on 2026-10-18 (Tandem 0.3.2): 97 automated tests and 14 installed-app checks passed. A real recording captured session keyboard input, arrow navigation, Backspace, shifted characters and three native button clicks as nine steps. Save → reload → replay reproduced the exact text and click order. Deleting one recorded click, saving and reloading replayed the remaining order. Starting a second recording from Repeat replaced the previous take and returned to Macros; its mouse-only take replayed in Background without moving the cursor or changing the active app. Clear → save → reload stayed empty with Play disabled. Six new regression tests cover navigation/function keys, already-held modifiers, excluded hotkeys, scroll target changes, held-key completion and shifted characters. The signed installed binary matches dist and passes strict signature verification. Three temporary macros and the test app were removed; clipboard contents were not read. See the [recording audit](../output/qa/recording-audit-2026-10-18.json).

Open Tandem, Settings and Clipboard opened correctly. A four-second delay-only macro verified live refresh after completion, global Play start/stop and emergency Stop All while the menu stayed open, plus both playback stop actions. Carbon hotkeys are drained during menu tracking so they are not held until dismissal. The temporary macro was removed; clipboard contents were not read. Local verification on 2026-10-17: 72 automated tests passed. A native two-window fixture received 15/15 background clicks while its window moved, with no clicks delivered to its sibling window and no cursor or foreground-app change. Closing the selected window stopped the run. An isolated Brave profile received 6/6 clicks on a page button and 6/6 on a canvas control, without changing focus or cursor position. These checks exercise specific controls, not every site or game.

Additional core checks used a protected event tap to record only marked synthetic click/text events, consuming those events before they reached applications. The captured mouse step replayed 3/3 background clicks. Six multi-point clicks alternated correctly between two windows (3/3 each), without emitting global mouse events or changing the active app. The closed-target check stopped with no sibling-window clicks. The signed installed panel also passed picking without dispatching a click, one background click through the global Start shortcut while Ace was active, and the global Clipboard shortcut. No fixed-point marker window was present in Background mode. Finite repeats now finish immediately after their last action, including at long intervals. These are controlled checks, not a guarantee that every app acknowledges every sent event.

Window movement or relayout during an individual click can drop that click; one earlier live run delivered 14 of 15 while moving. A subsequent controlled move between clicks delivered 15/15. The displayed counter counts sent actions, not target-app acknowledgments.

Roblox gameplay was not verified. Its [UserInputService documentation](https://create.roblox.com/docs/reference/engine/classes/UserInputService) states that gameplay input events require a focused client window; background gameplay support must not be advertised as universal.

Installed-app checks verified global macro play/stop, cancelling a delayed action, foreground text replacement, actual recording → save → background replay, and deleting the last recorded step → save → reload without restoring deleted steps. Native menus retain their items across unrelated view updates. Temporary test macros were removed and the original settings restored. See the [macro audit report](../output/qa/macros-audit-2026-10-17.json).

Delete-all → save → reload stayed empty, and Play was disabled for an empty macro. Actual recording → Clear Recording → save also stayed empty instead of restoring loaded actions. Pick Click Point consumed the setup click, retained the exact window and local point, and replayed one background click. The renamed installed app kept its existing permission and storage identity. Temporary macros and the fixture process were removed; the dark theme was restored. Interval display changed from 240000 ms to 4 min with the underlying interval unchanged.
